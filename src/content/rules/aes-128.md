order: 60
id: R-AES-128
title: AES below 256 bits is acceptable today; AES-256 is the high-assurance target
summary: Low-severity advisory for AES-128 and AES-192. Not a compliance failure and not a quantum deadline.
description: AES-128 and AES-192 remain NIST-approved with no retirement date. AES-256 is advised only where a CNSA 2.0 style high-assurance profile applies.
implementationStatus: active
appliesTo:
  - '*'
tags:
  - aes
  - symmetric
  - advisory
cases:
  - when:
      - field: algorithm
        op: equals
        value: AES
      - field: keySize
        op: lt
        value: 256
    result:
      title: AES-{{asset.keySize}} in use — AES-256 advised for high-assurance profiles
      severity: low
      regulatoryStatus: advisory
      migrationPosture: advisory
      effort: low
      hndlExposure: false
      currentCrypto: AES-{{asset.keySize}}
      recommendedReplacement: >-
        No action is required for general compliance. If the organisation follows NSA CNSA 2.0 or a comparable high-assurance profile, standardise new designs and key-management defaults on AES-256 (in Apex, 'AES256' with Crypto.generateAesKey(256)).
      rationale: >-
        AES-128 and AES-192 are approved by NIST with no scheduled retirement: NIST IR 8547 places AES-128 in post-quantum security category 1, and Grover's algorithm does not make a 128-bit key search practical. This is not a harvest-now-decrypt-later exposure. NSA CNSA 2.0, which is mandatory only for US national security systems, requires AES-256, so the finding is recorded as an advisory for organisations that align to that profile.
      citations:
        - NSA_CNSA_2_0
---
This rule is deliberately low-severity and carries no deadline. Earlier versions rated AES-128 as a medium finding with a 2030 date and harvest-now-decrypt-later exposure; no cited source supports that, so the rule now states only what CNSA 2.0 says.
